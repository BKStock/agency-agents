# R1〜R6・L1〜L6 定義台帳（`config/rules_v1.json`、rule_version 2026.10-draft.2）

本分類はプロジェクト独自のもので、公的な標準分類ではありません。閾値はすべて**未承認**です。そのため、エンジンは本版で `confirmed`（確定）を出力しません。

## 判定状態

| 値 | 表示 | 条件 |
|---|---|---|
| `confirmed` | 確定 | 条件を満たし、ルールが承認済みで、必要な外部証拠（等級 A/B）がある |
| `candidate` | 候補 | 条件は満たすが、未承認・証拠不足・排他条件の未解決のいずれか |
| `not_applicable` | 非該当 | 条件を満たさない／排他条件に該当／集落性の文脈がない |
| `on_hold` | 判定保留 | 外れた条件がすべて閾値近傍（±3%）にある／文脈が判定できない |
| `insufficient_data` | 資料不足 | 必要な特徴量が未取得（missing）または秘匿（suppressed） |
| `undeterminable` | 判定不能 | 分母が 0（無居住・面積 0）／合算元の町丁目 |

## 閾値の出所

| 区分 | 意味 |
|---|---|
| `user` | 指示書で利用者が提示した初期基準。採用は未承認 |
| `proposed` | 本設計の提案値。全国分布の分析後に承認が必要 |
| `approved` | 承認済み。`approved: true` の分類では、すべての閾値がこの区分でなければ読込を拒否する |

## 主分類・副分類

- R 軸と L 軸で、それぞれ主分類を決めます（`axis_result`）。L6 は対象外です。
- 該当した分類を、次の順に並べます。優先順位の固定表は持ちません。
  1. 確定度（確定 > 候補）
  2. 根拠等級（A > B > C）
  3. 根拠スコア
- 1位と2位の確定度・等級が同じで、スコア差が `min_margin`（0.10）未満なら、主分類は決めず `on_hold` とします。
- 町丁目全体で該当分類が2つ以上あれば、`overlap_flag` を付けます。

### 根拠等級

| 等級 | 条件 |
|---|---|
| A | 等級 A の外部証拠がある |
| B | 等級 B の外部証拠がある。または、証拠が不要な分類で条件を満たす |
| C | 必要な外部証拠がない |

### 根拠スコア

満たした条件の割合です。**確率や的中率ではありません。**

## 承認手順

1. 全国の特徴量の分布を、都道府県別・都市規模別に出力します。
2. 閾値の候補ごとに、該当・保留・資料不足の件数を比べます。
3. 正解ラベル（`gold_label`）で、分類別の適合率・再現率を確認します。
4. 承認したら、`origin` を `approved` に、`approved` を `true` にし、新しい `rule_version` として保存します。過去の run はそのまま残り、`atlas reproduce` で再現できます。
