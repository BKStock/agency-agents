## 2. 分類定義の改善提案

詳細は [class_definitions.md](class_definitions.md) にあります。

1. **R軸と L軸を独立させます。** 主分類も軸ごとに持ちます。地方都市の戸建地は R2 と L4 の両方に該当しえます。
2. **L6 は属性にします。** 主分類にはせず、集落性の文脈（L1〜L3、または DID 外）があるときだけ有効にします。
3. **R1 の地価は都道府県内の相対順位で比べます。**
4. **R3・R4・L5 は外部証拠がなければ確定しません。** この制約はルール読込時に強制し、ルールファイルからは外せません。国勢調査の周辺集計を証拠として登録しても拒否します。
5. **R5 は公営・UR の台帳で確定します。**
6. **L2 は、漁業集落の境界の入手可否で運用を分けます。**
7. **L4 は「三大都市圏外かつ都市雇用圏内」と定義します。**
8. **非住宅・無居住は分類を増やさず、軸の状態で表します。** `none` / `undeterminable` を使います。
9. **閾値の出所（user / proposed / approved）をルールに記録します。** 未承認の分類は確定を出しません。

## 3. L1〜L6 判定エンジン（R と共通）の詳細設計

`classify/engine.py` で、町丁目ごとに12分類すべてを評価します。

### 3.1 1分類の判定手順

1. 必要な特徴量が missing / suppressed なら、`insufficient_data` とします。理由に不足した特徴量名を書きます。
2. 分母が 0 なら、`undeterminable` とします。
3. 条件を満たさない場合：
   - 外れた条件がすべて閾値近傍（±3%）なら、`on_hold`
   - そうでなければ、`not_applicable`
4. 排他条件（R2 は R1 を除く）を確認します。
   - 相手が該当していれば、`not_applicable`
   - 相手が未解決なら、候補止まり
5. 文脈条件（L6）を確認します。
   - L1/L2/L3 のいずれかに該当、または DID 外なら有効
   - 判定できなければ `on_hold`、文脈がなければ `not_applicable`
6. 外部証拠（等級 A/B）とルールの承認を確認します。
   - どちらかが欠ければ `candidate`
   - どちらもそろえば `confirmed`

### 3.2 主分類

R軸と L軸で、それぞれ (確定度, 根拠等級, 根拠スコア) の順に並べます。

- 上位2件が拮抗した場合（同じ確定度・同じ等級でスコア差 < 0.10）は、主分類を決めず `on_hold` とします。
- 町丁目全体で該当分類が2つ以上あれば、`overlap_flag` を付けます。

### 3.3 秘匿と合算

| 町丁目の状態 | 扱い |
|---|---|
| 合算元 | 12分類すべて `undeterminable`（`merged_into:<合算先>`）。件数は合算先だけに入る |
| 秘匿 | 12分類すべて `insufficient_data` |
| 合算先 | 通常どおり判定し、根拠に `includes_merged_areas` を付ける |

### 3.4 再分類と再現

- 特徴量と外部証拠は `load_id` 付きで追記します。分類 run には、次を保存します。
  - ルール本文と SHA-256
  - 入力ハッシュ
  - 最大 `load_id`
  - コードの版
- `atlas reproduce --run-id` は、保存したルール本文と入力時点で再計算し、全行を照合します。
- 過去の run は、トリガーで UPDATE / DELETE を禁止しています。

### 3.5 出力構造

`regions.regional_classification` に、指示書 §6 の全列を持たせます。追加した列は次のとおりです。

- `run_id`、`boundary_version`、`axis`、`reason`、`evidence_json`

## 5. データベース設計

4つの SQLite ファイルを1接続に ATTACH します（`db/connection.py`）。

| DB | 主な表 | 役割 |
|---|---|---|
| `numbers` | `fetch_log`、`raw_file`（SHA-256）、`raw_source`（経路）、`version`、`designation_row`、`version_selection`、`diff_pair`、`diff_row`、`number_area_municipality` | 固定電話番号指定 DB |
| `regions` | `town`、`data_load`、`town_feature`（値＋状態）、`external_evidence`、`class_run`、`regional_classification`、`axis_result`、`gold_label` | 地域分類 DB |
| `evidence` | `facility_observation` | 公開施設番号エビデンス DB |
| `analysis`（main） | `pipeline_run`、`qa_result`、`priority_run`、`priority_item`、`evaluation_result` | 統合分析 DB |

DB をまたぐ統合ビュー（TEMP ビュー）：

- `municipality_code_relation`：区画レベルの関連
- `town_observed_code`：観測による関連

### 完全性を守る仕組み

- **先頭ゼロ**：コードは TEXT で保持し、float は拒否します。CHECK 制約で次を検証します。
  - 市外局番が 0 で始まること
  - 町丁目キー・市区町村コード・都道府県コードが互いに整合すること
- **欠損とゼロの区別**：CHECK 制約で強制します。`observed` / `zero` 以外の状態では、値は NULL でなければなりません。
- **原本・版・指定行・版選択・特徴量・証拠・分類・観測**は、すべて追記専用です。

## 6. GIS・統計解析の実装方法

`regions/gis.py` で計算します。

| 項目 | 方法 |
|---|---|
| 座標系 | 保存は JGD2011（EPSG:6668）。面積は GRS80 楕円体上の測地線面積で、平面直角座標系の系番号に依存しない（座標系を変えても同じ結果になることをテスト済み） |
| 取得範囲 | 範囲外にかかる町丁目は missing。面積 0 は undefined |
| 土地利用 | L03-b の区分コードごとの面積比 |
| DEM | GeoTIFF に変換したうえで、平均標高と平均傾斜。地理座標系では緯度に応じて画素の大きさを換算（合成 DEM で約 12.2° を検証済み） |
| 統計記号 | `-` は 0、`X` は秘匿、`…`・空欄は未取得（`normalize.stat_value`） |
| 時系列の組替え | [data_sources.md](data_sources.md) を参照 |

## 8. v1.2 の技術的問題と、新システムでの解消

v1.2 のコードは確認していないため、左列は共有された数値から**推測されるリスク**です。

| v1.2 で懸念される問題 | 新システムでの扱い |
|---|---|
| 変更行数（2,676 / 3,004）と、新規局番の種類数の混同 | 差分の要約で、延べと一意を常に並べて出す（`09b`、Q02/Q03） |
| 比較組の正当性（系統またぎ・隣接しない組） | 系統は表の中の市外局番（01〜09）から決め、隣接する選択版同士だけを比較する。Q01 で組を、Q12 で新旧の重なり率を検査する |
| Wayback と直接取得の二重計上 | 原本は SHA-256 で一意に保存し、経路は別の表に持つ。CDX の digest で重複取得も避ける |
| 同一基準日の差し替え版の選択基準が不明 | 規則で選び、候補と理由を `version_selection` に保存する（Q09） |
| 表形式変更による見かけの差分 | 原文を保持し、比較時に正規化して `cosmetic_only` に分ける（Q05） |
| xlrd の数値セルで先頭 0 が落ちる | 市外局番の 0 は補うが、`repaired` に記録して Q11 で可視化する |
| SHA-256 を取得時にしか計算しない | 原本を読むたびに再検証し、Q08 で全件を検査する |
| DB のその場更新で過去を戻せない | 追記専用。実行ごとにバックアップと復旧試験を行う |
| 41,987 行を全国件数と誤読する恐れ | 系統ごとの基準日を出力に残す（`selected_version`） |
| 単一スクリプトへの機能集中 | 取得・解析・履歴・地域・分類・関連・出力を、別モジュール・別 DB に分ける |

## 11. 最初にやるべき3工程

1. **実データでの初回取得（P0）**
   - `atlas init` → `atlas update`（Wayback なし）を実行します。
   - 停止したら、`atlas qa` と `run_manifest.json` を見て、`layouts.json` / `sources.json` / `in_use_values` を直します。
   - 完了条件：`outcome: ok` で、全系統の最新版が選択されていること。
2. **過去版の収集と履歴の確認（P0）**
   - `atlas update --wayback` で過去版を集めます。
   - 差分の要約（延べ・一意・種別）と、同一基準日の選択理由を確認します。
   - v1.2 の報告値（23組・2,676行・3,004行）とは、参考として突き合わせます。定義が違えば数値も違うので、一致させることは目的にしません。
3. **2020 年小地域の取込と一次判定（P1）**
   - 大阪府と、農山漁村を含む比較用の3県から始めます。
   - `atlas import-census` → `atlas classify` → `atlas export` を実行します。
   - 候補・保留・資料不足の件数と特徴量の分布をもとに、閾値承認の資料を作ります（確定は 0 件のまま）。

## 12. 代替案

| 案 | メリット | デメリット | 判断 |

| 500m メッシュを補助的な分析単位にする | 境界変更に強く、時系列比較が容易 | 按分で誤差が出る | 人口の組替え・補完に採用 |
